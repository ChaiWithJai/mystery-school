# Contribute to Mystery School

Start with the [README](README.md) and [architecture](docs/architecture.md). Keep changes focused on a working learner interaction and the evidence needed to review it.

## Prepare a change

Create an isolated branch or worktree, especially while another builder presents from the main checkout. State the problem, resulting behavior, and implementation limits in the pull request. Preserve learner wording, source attribution, actor labels, and immutable artifact relationships.

Run the checks relevant to your change using the [verification guide](docs/verification-guide.md). For documentation-only changes, verify links and commands; do not claim unrun runtime tests. For interface changes, include actual browser evidence. Separate fixtures from human learning results and model availability from model accuracy.

## Write and review documentation

Follow the [documentation standard](docs/documentation-standard.md). Update the README or guide when a feature changes. Keep dated evidence intact and identify superseded setup instructions. Do not commit credentials, model weights, private recordings, or local student records.

Review the [reuse ledger](docs/sources-and-reuse.md) before importing code or assets. This repository has no repository-wide license grant; do not invent one for a contribution.
