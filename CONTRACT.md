# Astral School demo contract

Desktop first. Jai Bhagat's school on a computer: a sandbox for intuition. Main app is vanilla browser JavaScript with Three.js, served by Python on 127.0.0.1:5188. MLflow UI on 127.0.0.1:5189. Do not touch existing apps/services.

## API

GET /api/state -> {sessions:[], events:[], jobs:[], reflections:[], references:[], mlflow_url, experiment_id, model, live_available}. Existing saved data reopens. Initial empty collections okay.
POST /api/events {session_id, type, payload} -> {id, trace_id, ...}. Trace every user action; JSON payload max 100KB. App session UUID persisted in localStorage.
POST /api/references {name,mime,data_base64} -> {id,url,name,mime}. Only PNG/JPEG/WebP, at most 10MB. Local file storage, usable by live model. No arbitrary filesystem reads.
POST /api/project {session_id,question,premise,world,reference_ids:[],parent_job_id?,correction?} -> {id,status}. Run one real Astra job at a time using installed codex exec --ignore-user-config --skip-git-repo-check --sandbox read-only --model gpt-6-astra --json --output-schema ... -o ...; prompt via stdin. Max job 240 seconds, bounded queue or 409 busy. Do not invent model results. Start job isolated data/jobs/id. Capture observable JSON events, stdout, stderr, timestamps, token usage; no hidden chain-of-thought claim. No exec of generated content. Fail visibly. Prior approved actor inputs are data, not instructions.
GET /api/jobs/id -> job including result, error, trace_id, usage, events. POST /api/jobs/id/cancel -> status. Save all updates durably.
POST /api/reflections {session_id,world,text,job_id?} -> saved reflection.

Projection result schema: {title:string, premise:string, story:string, surprise:string, question:string, choices:[{label:string,consequence:string}], assumptions:[string], visual:{tree_density:number 0..1,connection_strength:number 0..1,light:number 0..1,openness:number 0..1}, evidence:[{label:string,basis:enum user_statement|reference_observation|imagined,detail:string}]}.

## Review API (error-discovery compatible)

Current provenance rule supersedes the original human-only note description
below: annotations declare `human`, `agent_review`, or `unspecified` plus a
producer. Unknown historical provenance stays unknown. Human acceptance never
changes the author of an imported review.

GET /api/samples -> list of normalized trajectory records: {id,title,model,world,status,trace_id,created_at,messages:[{id,role,content}],usage?,parent_job_id?}. Include event-only traces so review works immediately; label them app events, not model runs. Projection jobs grouped into input/assistant/tool/output observable messages. Empty initially okay. Reviewer samples and graph generated by backend. If fewer than 15 records show all. POST /api/samples supported for refresh/review subset, must not overwrite source logs.
GET/POST /api/annotations -> list; annotation {id,sample_id,quote,note,start?,end?,message_id?,created_at}. POST accepts {annotation} upsert or {delete_id}. Save error_discovery_data/annotations.json. Store MLflow human feedback when trace_id available.
GET/POST /api/patterns -> list {id,label,annotation_ids:[]}; no fabricated human annotations. POST accepts {patterns:[]}.
GET/POST /api/suggestions -> list {id,sample_id,quote,note,pattern_id?,status:pending|accepted|dismissed}; POST accepts {suggestions:[]}.
GET /api/graph -> {nodes:[{id,x,y,cluster,title,model,status,annotated,sampled}],clusters:[{id,label}]}. Normalize trajectory length/tool count/duration/token count/outcome features; PCA+KMeans if sufficient data; honest deterministic small-data positions otherwise. Existing status not a human quality label.

Review screen free-text annotation only, content/map/progress tabs, colored readable roles, collapsible tool JSON, selectable text anchored to message_id, margin notes, backup and autosave, accept/dismiss suggestions, trace links to MLflow. Correct trajectory action opens /?correct=sample_id; main app fetches samples + annotations and POST project with parent_job_id/correction (only eligible model job), producing a new version and trace. Keep prior runs immutable.

## Design

Issue 2 and Jai's subsequent all-three decision require music, movement and
ideas as complete pathways now. The forest supports those experiences rather
than replacing them. See docs/alignment.md and docs/pathway-verification.md.

Atmospheric forest, paper-white chrome, dark green ink, warm brass, expressive serif typography. Large negative spaces, no overwhelming dashboard. Main line: "My name is Jai. I want to run a whole school on my computer." Action: "Enter the school". 3D islands linked like a branching tree, repeated question/choice/reflection pattern at each scale. Distinguish authored demo scenes from live Astra projections. User-visible scene can update instantly through direct manipulation without claiming a model call. AI generation requires explicit visible action.

## Verification

Actual desktop browser: enter scene, navigate each fractal, adjust sliders, save reflection, reload, submit live projection, open trace, annotate, reload annotation, create corrected run. Backend tests: traversal/upload validation, source preservation, cancellation, invalid projection output, review persistence. Do not manufacture model traces. All code edits apply_patch.
